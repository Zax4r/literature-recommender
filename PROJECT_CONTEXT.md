# Контекст проекта: интеллектуальная система подбора литературы

Файл для ИИ-помощников и новых участников: что это за приложение, как оно устроено и где что лежит. Всё ниже
проверено по коду репозитория. Подробности запуска и API есть также в `README.md`.

## Что это

Курсовой проект (БГУИР, кафедра интеллектуальных информационных технологий). Пользователь описывает, что хочет
почитать (текстом, голосом или файлом), и получает подборку похожих книг с коротким пояснением и ссылками на магазины
Беларуси. У пользователя есть профиль, личная библиотека (статусы чтения, оценки, избранное), а теги книг (жанры и
тропы) можно предлагать и оценивать голосованием.

Каталог: 6556 книг. Карточка книги: название, автор, аннотация, жанры, тропы. Язык интерфейса и каталога русский,
названия многих книг английские.

## Состав системы

| Часть | Технологии | Назначение |
|---|---|---|
| Бэкенд | Python 3.12, FastAPI, SQLAlchemy 2, Alembic, PostgreSQL 17 | Аккаунты, каталог, библиотека, теги, история, сессии чата |
| Чат (решатель задач) | Агенты на LLM через OpenRouter, Qdrant, sentence-transformers, faster-whisper | Подбор книг по свободному запросу |
| Фронтенд | React 18, Vite, TypeScript, nginx | Отдельное веб-приложение, `/api` проксируется на бэкенд |
| Хранилища | PostgreSQL (знания и профили), Qdrant (индекс каталога) | Связаны общим ключом `books.source_idx` |

Запуск целиком: `cp .env.example .env`, вписать `OPENROUTER_API_KEY` и `SECRET_KEY`, затем `docker compose up --build`.
Сервисы: `db` (Postgres, порт хоста 5435), `qdrant` (6333), `init` (разово: миграции, загрузка каталога в Postgres и
Qdrant, создание тегов; первый запуск около 7 минут), `api` (8000), `frontend` (3000). Админ из миграции: `admin` /
`admin` (только для разработки). Swagger: `http://localhost:8000/docs`.

## Как работает подбор (чат)

Оркестратор: `app/services/ai/orchestrator.py`, функция `run_chat`. Этапы:

1. **Ввод.** Текст, аудио (локальное распознавание речи, faster-whisper на CPU) или файл (txt, md, pdf, docx). Размер
   файла до 25 МБ, текст из файла обрезается до 20000 символов, текст запроса для роутера до 2000 символов.
2. **Router** (LLM): определяет намерение `recommend | follow_up | clarify | refuse | unsafe`, риск (`low | high`) и
   краткую суть запроса. Для `unsafe` и `refuse` возвращается готовый отказ, поиск не выполняется. `clarify` и
   `follow_up` возвращают вопрос или подсказку без поиска.
3. **Extractor** (LLM): жанры, тропы и исключения (по 8 элементов, до 60 символов). Повторы и некорректные значения
   отбрасываются (`app/services/ai/guard.py`).
4. **Поисковый запрос**: строка из сути запроса, `ЖАНРЫ: ...` и `ТРОПЫ: ...`.
5. **Исключения по профилю**: книги пользователя со статусами `read`, `reading`, `dropped` (`app/services/ai/context.py`).
   Статусы `planned` и избранное не исключаются.
6. **Гибридный поиск** (`app/services/search/qdrant_search.py`): две ветки в Qdrant (dense `multilingual-e5-base` и sparse
   BM25), по 40 кандидатов каждая, слияние RRF, запрашивается `SEARCH_TOP_K * 5 = 30` кандидатов. Фильтры: исключаемые
   тропы и `source_idx` (в фильтр попадает не более 50 значений). При ошибке гибридного индекса используется
   резервный dense-поиск.
7. **Отбор по жанрам** (`prefer_genres`): если среди кандидатов есть книги с запрошенным жанром в жанрах или тропах,
   остаются только они. Затем выдача сокращается до 6 книг.
8. **Параллельно**: Formatter (LLM, 2-4 предложения пояснения) и поиск магазинов. Магазины: либо веб-поиск агентом (если
   `SHOP_SEARCH_ENABLED=true`, только домены из белого списка), либо ссылки-шаблоны на поиск в OZ.by, Литрес, Лабиринт,
   Goodreads. Магазины ищутся для первых 3 книг (`SHOP_MAX_BOOKS`) при веб-поиске.
9. **Ответ**: намерение, текст, карточки (`source_idx`, название, автор, жанры, тропы, описание до 600 символов, оценка,
   ссылки), совпавшие признаки. Для авторизованных ответ сохраняется в историю рекомендаций.

Устойчивость: у каждого LLM-этапа жёсткий лимит времени (агенты 15 с, поиск 20 с, магазины 15 с) и запасное значение при
сбое или таймауте (`_bounded`). Например, при таймауте экстрактора поиск идёт без жанров и троп. Один запрос в чат делает
3 вызова LLM, а при веб-поиске магазинов ещё один.

Защита от prompt injection (`guard.py` и тексты в `prompts/`): пользовательский текст и текст файла всегда оборачиваются
как недоверенные данные, простая проверка по шаблонам (русские и английские фразы), ответы моделей принимаются только как
валидный JSON с проверкой типов и длины, ссылки магазинов фильтруются по белому списку доменов.

## Данные

Миграции в `alembic/versions/` (0001 каталог, 0002 пользователи и админ, 0003 пользовательские данные, 0004 сессии
чата). Таблицы:

- `users` (email, username, пароль в виде хэша, display_name, bio, is_admin).
- `books` (`id`, `source_idx` уникальный и общий с Qdrant, title, author, description, `genres[]`, `tropes[]`).
- `tags`, `book_tags` (вес, равен позиции в карточке, 0 для пользовательских тегов), `tag_votes` (значение +1/-1,
  первичный ключ `(user_id, book_id, tag_id)`).
- `user_books` (статус `read | reading | dropped | planned`, оценка 1-5), `favorites`.
- `chat_sessions`, `chat_messages` (с JSON `payload` для карточек).
- `recommendations`, `recommendation_items` (позиция, причина, ссылки магазинов).

Теги создаются командой `python -m app.cli sync-tags` из жанров и троп (около 20,5 тыс. тегов). Оценка тега равна сумме
голосов, порядок: сумма голосов, затем вес.

Каталог создаётся пайплайном `scripts/` (`run_pipeline`): исходный список в `scripts/data/1_raw_lists/books.csv`,
карточки генерирует LLM по `prompts/metadata_generator_prompt.txt`, результат в `scripts/data/2_generated_jsons/books.json`,
кэш векторов в `scripts/data/3_embeddings`.

## API (кратко)

Префикс `/api/v1`, авторизация `Authorization: Bearer <JWT>` (срок 24 часа). Основные группы:
`/auth` (регистрация, вход), `/users` (профиль, избранное, библиотека), `/books` (лента, карточка, избранное, статус и
оценка, теги и голоса), `/recommendations` (история), `/chat/sessions` (сохранённые беседы; отправка сообщения возвращает
ответ потоком `text/event-stream` с событиями `user`, `message`, `error`), `/chat` (разовый запрос, в том числе анонимный),
`/chat/transcribe` (отладка речи), `/health`. Списки возвращают `{items, total, offset, limit}`. Полная таблица в README.

## Настройки по умолчанию (`app/core/config.py`)

Модели по умолчанию `openai/gpt-4o-mini` (router, extractor, formatter). README описывает бесплатный профиль на
`nvidia/nemotron-3.5-super-vl:free` с `SHOP_SEARCH_ENABLED=false`, он задаётся в `.env`. Эмбеддинги
`intfloat/multilingual-e5-base`, `SEARCH_TOP_K=6`, `SEARCH_PREFETCH_K=40`, Whisper `small` на CPU (`int8`). Белый список
магазинов: oz.by, ozon.by, ozon.ru, wildberries.by, books.by, labirint.ru, book24.ru, litres.by, litres.ru, mybook.ru.

## Известные ограничения и наблюдения

- Оценки и избранное сохраняются и показываются, но на порядок рекомендаций не влияют: учитывается только статус
  (`read`, `reading`, `dropped` исключаются).
- В фильтр исключения поиска попадает не более 50 значений: у читателя с большей библиотекой часть прочитанных книг
  может снова попасть в подборку.
- С бесплатной моделью запрос в чат занимает десятки секунд (в проверке около 33 с), экстрактор может не уложиться в
  15 секунд, тогда поиск идёт без жанров и троп и выдача хуже. Лимиты бесплатного OpenRouter: около 20 запросов в минуту
  и 50 в сутки.
- Голосовой ввод проверен только на эндпоинте распознавания; Whisper при тишине может вернуть случайный текст.
- У каталога нет обложек, авторы хранятся одной строкой (иногда через `;`).
- В интерфейсе активная вкладка «Чат» сразу после перехода на мгновение плохо читается (белый текст на светлом фоне), а в
  сайдбаре длинное название беседы вызывает горизонтальную прокрутку.
