# Интеллектуальная система подбора литературы

Курсовой проект. Пользователь описывает, какую книгу он хочет (текстом или файлом), и получает подборку похожих книг
с объяснением и ссылкой на магазин. У пользователя есть профиль, личная библиотека (прочитал / читаю / брошено / в планах,
оценки, избранное), а теги книг можно предлагать и оценивать голосованием.

Этот репозиторий содержит **бэкенд** (FastAPI + PostgreSQL) и минимальный веб-интерфейс для проверки. Сервис ИИ
(эмбеддинги, гибридный поиск, Whisper) делается отдельно и подключается через интерфейс, см. [Рекомендации](#рекомендации-и-сервис-ии).

## Что умеет бэкенд

| Область | Возможности |
|---|---|
| Аккаунты | Регистрация, вход по email или логину (JWT), профиль (имя, о себе), публичный профиль |
| Каталог | Импорт книг из датасета UCSD Book Graph (только админ), лента с `offset`/`limit`, карточка книги (название, авторы, первые 250 символов описания) |
| Избранное | Добавить и убрать книгу, список избранного с пагинацией |
| Библиотека | Статус книги (`read`, `reading`, `dropped`, `planned`), оценка 1–5, фильтр списка по статусу |
| Теги | Теги из полок датасета, предложение своих тегов, голосование «за» и «против» (один голос на пользователя), рейтинг тега |
| Рекомендации | Запрос текстом или `.txt` файлом, причина для каждой книги, ссылка на поиск в магазине, история запросов |
| Веб-интерфейс | Одна страница на `/`: вход, лента, избранное, библиотека, теги с голосованием, рекомендации |

## Быстрый старт

Нужны Docker и [uv](https://docs.astral.sh/uv/).

```bash
cp .env.example .env          # впишите свой SECRET_KEY
docker compose up --build
```

Дальше:

- Веб-интерфейс: http://localhost:8000/
- Swagger: http://localhost:8000/docs
- Миграции применяются автоматически при старте контейнера.
- Войдите как `admin` / `admin` и нажмите «Импорт 100 книг» (около 3 секунд).

> **Админ `admin` / `admin` создаётся миграцией и нужен только для разработки.** Перед любым реальным запуском
> смените пароль и `SECRET_KEY`.

### Локальная разработка без Docker для API

```bash
uv sync
docker run -d --name lit-pg -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=literature -p 5432:5432 postgres:17
uv run alembic upgrade head
uv run uvicorn app.main:app --reload
```

`DATABASE_URL` по умолчанию указывает на `localhost:5432`, так что `.env` для этого не нужен.

### Проверки

```bash
uv run ruff check . && uv run ruff format --check .
uv run mypy .
uv run pytest                  # 25 тестов, SQLite в памяти, сеть не нужна
```

Новая миграция: `uv run alembic revision --autogenerate -m "описание"`. Новые модели надо импортировать в
`app/models/__init__.py`, иначе Alembic их не увидит.

## API

Префикс `/api/v1`. Защищённые методы ждут заголовок `Authorization: Bearer <токен>`.
Списки возвращают `{items, total, offset, limit}`, `limit` от 1 до 100 (по умолчанию 20).

### Аккаунты

| Метод | Путь | Доступ | Описание |
|---|---|---|---|
| POST | `/auth/register` | все | `{email, username, password}`, пароль от 8 символов |
| POST | `/auth/login` | все | форма: `username` (email или логин) и `password`, возвращает JWT |
| GET / PATCH | `/users/me` | токен | свой профиль (`display_name`, `bio`) |
| GET | `/users/{username}` | все | публичный профиль без email |

### Книги и избранное

| Метод | Путь | Доступ | Описание |
|---|---|---|---|
| POST | `/books/import?count=100` | админ | импорт первых подходящих книг из UCSD, повторный вызов ничего не дублирует |
| GET | `/books?offset=&limit=` | все | лента книг |
| GET | `/books/{id}` | все | карточка: авторы, 250 символов описания, теги, `store_url` |
| PUT / DELETE | `/books/{id}/favorite` | токен | в избранное и обратно (204, повтор безопасен) |
| GET | `/users/me/favorites` | токен | избранное |

С токеном лента и карточка дополнительно содержат `is_favorite`, `status` и `rating` текущего пользователя.

### Библиотека

| Метод | Путь | Доступ | Описание |
|---|---|---|---|
| PUT | `/books/{id}/entry` | токен | `{"status": "read\|reading\|dropped\|planned", "rating": 1..5 или null}` |
| DELETE | `/books/{id}/entry` | токен | убрать с полки |
| GET | `/users/me/library?status=` | токен | полка, фильтр по статусу необязателен |

### Теги

| Метод | Путь | Доступ | Описание |
|---|---|---|---|
| POST | `/books/{id}/tags` | токен | `{"name": "slow burn"}`: имя нормализуется в `slow-burn`, тег получает ваш голос «за» |
| PUT | `/books/{id}/tags/{name}/vote` | токен | `{"value": 1}` или `{"value": -1}`, повторный голос заменяет предыдущий |
| DELETE | `/books/{id}/tags/{name}/vote` | токен | убрать свой голос |

Каждый ответ по тегам содержит список `{name, score, my_vote}`. `score` равен сумме голосов. Теги сортируются по
`score`, затем по числу полок в датасете.

### Рекомендации

| Метод | Путь | Доступ | Описание |
|---|---|---|---|
| POST | `/recommendations` | токен | `{"query": "..."}` (до 2000 символов) |
| POST | `/recommendations/file` | токен | multipart-поле `file`: текст UTF-8 до 100 КБ |
| GET | `/recommendations` | токен | своя история |
| GET | `/recommendations/{id}` | токен | один запрос (чужой даёт 404) |

Ответ: для каждой книги `book` (как в ленте), `reason` и `store_url`. Книги со статусами `read`, `reading`, `dropped`
в выдачу не попадают.

## Модель данных

```
users ─┬─ favorites ──────────┐
       ├─ user_books ─────────┤
       ├─ recommendations ─ recommendation_items ─┐
       └─ tag_votes ─┐        │                   │
                     │      books ── book_authors ── authors
tags ── book_tags ───┴────────┘
```

- `books` хранит `goodreads_id` (уникальный), название, полное описание, обложку и ссылку.
- `book_tags.weight` равен числу пользователей Goodreads, поставивших книге эту полку. У добавленных тегов он 0.
- `tag_votes`: первичный ключ `(user_id, book_id, tag_id)`, поэтому один пользователь не может голосовать дважды.
- `user_books`: статус и оценка пользователя для книги.

## Данные и тегирование

Книги берутся из [UCSD Book Graph](https://mcauleylab.ucsd.edu/public_datasets/gdrive/goodreads/UCSD%20Book%20Graph.html)
(данные Goodreads). Файл книг (около 2 ГБ) целиком не скачивается: импорт читает его потоком и останавливается,
когда набрано нужное число книг. Имена авторов берутся из отдельного файла (около 18 МБ).

Записи без названия или описания пропускаются, HTML в описаниях очищается. Из `popular_shelves` отбрасываются полки,
описывающие состояние читателя (`to-read`, `owned`, `favorites` и подобные) и редкие (меньше 2 пользователей),
остаются 10 самых популярных.

Повторный импорт пропускает уже известные книги и не добавляет им теги. Чтобы пересобрать данные, очистите таблицу
`books`.

> **Лицензия данных.** Датасет собран только для академического использования: его нельзя использовать в коммерческих
> целях и распространять. Не добавляйте данные в репозиторий и не выкладывайте сервис с ними публично. В отчёте нужно
> сослаться на: Wan & McAuley, *Item Recommendation on Monotonic Behavior Chains*, RecSys'18; Wan, Misra, Nakashole &
> McAuley, *Fine-Grained Spoiler Detection from Large-Scale Review Corpora*, ACL'19.

## Рекомендации и сервис ИИ

Граница между бэкендом и ИИ описана в `app/services/recommender.py`:

- `RecommendationRequest(text, user_id)` на входе.
- `Recommended(book_id, reason)` на выходе.
- `Recommender` это интерфейс с одним методом `recommend`.

Сейчас его реализует **`KeywordRecommender`, заглушка без ИИ**: она ищет совпадения слов запроса с названиями и тегами
книг. Запросы на русском находят книги только по названиям, потому что теги английские. Чтобы подключить настоящий
сервис, достаточно написать реализацию `Recommender` (например, HTTP-клиент) и вернуть её из `get_recommender`
в `app/api/routes/recommendations.py`. Остальной код менять не нужно.

Голосовой ввод (Whisper) бэкенд не обрабатывает: распознавание речи относится к сервису ИИ. Файлы принимаются только
текстовые.

## Как проверено

- 25 автотестов (`pytest`) покрывают аккаунты, импорт и очистку полок, ленту, избранное, теги, библиотеку и рекомендации.
- Полный сценарий из 54 проверок пройден через HTTP на стеке из `docker compose` (PostgreSQL 17): регистрация и вход,
  права админа, импорт и идемпотентность, пагинация, голосование, библиотека, рекомендации по тексту и файлу, приватность
  истории, коды ошибок 401, 403, 404 и 422, сохранение данных после перезапуска контейнера API.
- Веб-интерфейс проверен в браузере: вход, лента, диалог книги, голосование, статусы, рекомендации, консоль без ошибок.

## Что пока не сделано

- Настоящий сервис рекомендаций и голосовой ввод (зона ответственности ИИ-части).
- Модерация тегов: пользователь может предложить любое допустимое по формату имя.
- Импорт выполняется синхронно в запросе (для сотен книг нормально, для тысяч нужна фоновая задача).
- Refresh-токены, смена пароля, ограничение частоты запросов на вход.
- CI (GitHub Actions), тесты на PostgreSQL вместо SQLite.
- Поиск и фильтрация ленты по названию, автору и тегу.
- Русскоязычные источники книг: открытых датасетов у ЛитРес и ЛайвЛиб нет, парсить их без разрешения нельзя.
